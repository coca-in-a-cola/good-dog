**Retrospective sourcing correction (F2 remains blocked, not accepted):** The initial F2 integration skipped the separate Godot Asset Library search required by GDD §2 and selected GitHub candidates directly. This was a process deviation, not compliant original search order. A retrospective Asset Library API check on 2026-10-29 (+05) found the selected ar-bh controller as [asset 5421](https://godotengine.org/asset-library/asset/5421) (MIT, 1.0.0), whose catalog download commit is exactly `7f50a91a7063106047a06bd8d6c200cdda80f3b2`, matching the verified vendored source. Alternatives 3475, 3890, 2418 and 3646 were considered; no replacement is justified for the F2 repair slice. Retain that pin, acknowledge the deviation, and perform the prescribed ordered lookup before later subsystem implementation. This retrospective evidence does not repair the original chronology. Acceleration tuning remains a separately tracked F3/F6 limitation. Evidence: private ledger `sourcing-preflight/REPORT.md` and its retained API responses; no alternative assets imported.

## Release packaging: notices beside the executable

`export_presets.cfg` packs the notices into the PCK. Players also need them as plain files beside `good-dog.x86_64` / `good-dog.exe`. `tools/release/notices_manifest.json` lists every file. `tools/release/package_notices.gd` copies them byte-for-byte (`--copy <export dir>`) and verifies presence and identity (`--check <export dir>`). Sources: `LICENSE` (original MIT, unmodified), `THIRD_PARTY.md`, both OFL texts, the basic_fps_controller MIT `LICENSE.txt` and the camera-flash CC0 provenance. Godot's `LICENSE` and third-party component notices are written verbatim from `Engine.get_license_text()`, `get_copyright_info()` and `get_license_info()` of the 4.7.2 engine, which must match the export templates. Dependencies keep their own licenses and are not relicensed. Run `--copy` then `--check` for both Linux and Windows after `--export-release`, before archiving.
